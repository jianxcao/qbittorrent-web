# i18n 翻译检查和清理技能

这个技能帮助你全面检查和优化 qb-web 项目的 Vue i18n 翻译文件。

## 功能特性

✅ **缺失翻译检测**: 找出代码中使用但翻译文件中不存在的 key  
✅ **语言一致性检查**: 确保所有语言文件的 key 结构一致  
✅ **空值检测**: 识别值为空的翻译项  
✅ **未使用 key 清理**: 自动删除翻译文件中未被使用的 key  
✅ **重复翻译检测**: 发现相同翻译值，建议提取为公共 key  
✅ **自动备份**: 清理前自动备份原文件

## 使用方法

### 方式 1: 通过 AI 助手

直接在 Cursor 中对 AI 说：

```
帮我检查一下 i18n 翻译
```

或者：

```
清理未使用的翻译 key
```

或者：

```
检查是否有重复的翻译
```

AI 会自动应用这个技能并执行完整的检查流程。

### 方式 2: 手动运行脚本

在项目根目录下运行：

```bash
node .cursor/skills/i18n-checker/check-i18n.js
```

## 检查项说明

### 1. 缺失的翻译 (高优先级 ❌)

代码中使用了某个翻译 key，但在翻译文件中找不到对应的定义。

**影响**: 页面会显示 key 本身而非翻译文本。

**修复**: 在 `zh-CN.json` 和 `en-US.json` 中添加对应的翻译。

### 2. 语言不一致 (高优先级 ⚠️)

不同语言文件的 key 结构不一致，比如 zh-CN 有某个 key 但 en-US 没有。

**影响**: 切换语言时可能显示错误或缺失翻译。

**修复**: 确保所有语言文件都包含相同的 key 结构。

### 3. 空值翻译 (中优先级 ⚠️)

翻译文件中某些 key 的值为空字符串或 null。

**影响**: 页面可能显示空白。

**修复**: 为这些 key 填充正确的翻译文本。

### 4. 未使用的 key (自动清理 🗑️)

翻译文件中存在但代码中从未使用的 key。

**影响**: 增加翻译文件体积，造成维护困扰。

**处理**: **自动删除**（会先备份原文件）。

### 5. 重复翻译 (优化建议 💡)

多个不同的 key 指向相同的翻译文本。

**影响**: 增加维护成本，未来修改时可能遗漏某些位置。

**建议**: 考虑提取为公共 key（如 `common.operationSuccess`），需要人工判断是否合理。

## 备份和恢复

脚本会在删除未使用的 key 前自动备份翻译文件：

- 原文件: `zh-CN.json`
- 备份文件: `zh-CN.json.backup`

如果需要恢复：

```bash
# 恢复中文翻译
cp src/i18n/locales/zh-CN.json.backup src/i18n/locales/zh-CN.json

# 恢复英文翻译
cp src/i18n/locales/en-US.json.backup src/i18n/locales/en-US.json
```

## 最佳实践

1. **定期检查**: 建议在每次提交前运行检查
2. **先修复后清理**: 优先处理缺失的翻译和不一致问题
3. **谨慎提取公共 key**: 评估是否真的应该共用翻译
4. **保持 key 语义化**: 使用描述性的 key 名称
5. **统一命名空间**: 通用翻译放在 `common` 下

## 常见问题

### Q: 脚本会修改哪些文件？

A: 只会修改翻译文件（`src/i18n/locales/*.json`），且只删除未使用的 key。修改前会自动备份。

### Q: 如何处理动态构造的 key？

A: 脚本无法检测动态 key（如 `` t(`status.${state}`) ``）。如果你使用动态 key，请手动检查这些 key 是否存在于翻译文件中。

### Q: 重复翻译一定要提取吗？

A: 不一定。虽然文字相同，但如果语义不同或未来可能独立修改，就不应该提取。脚本只是提供建议，需要人工判断。

### Q: 删除的 key 可以恢复吗？

A: 可以。脚本会创建 `.backup` 备份文件，你可以随时恢复。也可以通过 git 恢复到之前的版本。
